# Syria Delivery Deep Audit

## Scope

The archive contains **three Flutter applications** (`customer_app`, `courier_app`, and `merchant_app`) plus one React/Vite web application (`admin-dashboard`). There is no fourth Flutter project; the administration panel is the fourth web project.

## Web compatibility review

The three Flutter `pubspec.yaml` files use the same Firebase and web-capable UI stack: `firebase_core`, `firebase_auth`, `cloud_firestore`, `cloud_functions`, `flutter_map`, `latlong2`, `geolocator`, `firebase_messaging`, and `url_launcher`. A source scan found no imports of `dart:io`, `dart:ffi`, `path_provider`, `shared_preferences`, `permission_handler`, or `flutter_secure_storage`.

`geolocator`, `firebase_messaging`, and `url_launcher` are potentially platform-sensitive packages, but all are web-supported at the package level. The source uses a `kIsWeb` guard before requesting push permission/token in the customer and courier apps, so web startup does not require mobile notification configuration. Location functionality is only used by the courier app and may require browser location permission at runtime; it should not prevent compilation.

## Firebase Emulator review

All three Flutter apps now call `Firebase.initializeApp()` followed by `connectToFirebaseEmulators()` from their bootstrap functions. The emulator switch defaults to `false` for production safety and can be enabled explicitly with `--dart-define=USE_FIREBASE_EMULATORS=true`. Web builds receive Firebase configuration through `FIREBASE_*` build defines, while mobile builds use the platform configuration generated by `flutterfire configure`. The host defaults to `127.0.0.1` on web, with `EMULATOR_HOST` available as an override.

The admin dashboard connects to Auth, Firestore, and Functions emulators automatically when Vite runs in development mode (`import.meta.env.DEV`).

## Launcher ports

`start.bat` now uses deterministic ports:

| Project | Command port |
|---|---:|
| Admin dashboard | 5173 |
| Customer app | 3000 |
| Courier app | 3001 |

The Flutter apps are launched with `-d chrome`. The admin dashboard is launched with Vite `--host 127.0.0.1 --port 5173 --strictPort`.

## Recommended Windows verification

From the extracted project root, run:

```bat
flutter doctor
cd customer_app && flutter clean && flutter pub get && flutter build web --verbose --web-renderer canvaskit
cd ..\courier_app && flutter clean && flutter pub get && flutter build web --verbose --web-renderer canvaskit
cd ..\merchant_app && flutter clean && flutter pub get && flutter build web --verbose --web-renderer canvaskit
cd ..\admin-dashboard && npm install && npm run build && npm run lint
```

Then run `start.bat`. The expected local URLs are `http://localhost:5173`, `http://localhost:3000`, `http://localhost:3001`, and `http://localhost:3002`.

> Note: If the installed Flutter version rejects `--web-renderer canvaskit`, omit that optional flag and rerun `flutter build web --verbose`.

The package-version message about newer incompatible versions is informational and is not itself a build failure.

## Follow-up compilation fix

A source audit after the first archive found one definite customer compilation blocker: `customer_app/lib/screens/home_screen.dart` called `vendorIsOpen(data)` while the helper was absent from `customer_app/lib/common.dart`. The helper has now been added with safe opening-hours parsing and a fallback to open when data is malformed. This fix is included in the final follow-up archive.
